# 0.5.0-rc.17

This candidate includes the fixes merged in #70 and #71 after v0.5.0-rc.16.

## Browser bridge

The rc.16 application image could return `500 text/plain` for browser bridge
POST requests because the active ORCE HTTP In node resolved an incompatible
`raw-body` export. The PCI image build now applies a compatibility workaround
to that module, retains the installed `body-parser`, and stops parsing when
it is skipped or the completed stream already has a parsed body.

The original module's SHA-256 is recorded in `deployment/image/base-image.lock`.
A different source file fails the build and requires review.

The Images workflow starts the built image using its production entrypoint.
Both requests use the configured main host and same-origin JSON headers.
An empty object must return a 400 JSON validation error. A valid socket ID
must return a 200 JSON bridge grant with a token and expiry.

## BDD dependencies

The tracked patch removes the unused `licensecheck` runtime dependency from
the pinned BDD Executor. The Markdown constraint is removed. Requests remains
pinned to 2.33.0. The seven BDD compatibility tests passed on the cleanup branch.

The cleanup branch's Dash scan reported unresolved findings for Pillow 13.0.0
and PrettyTable 3.19.0. The release-tag scan supplies the result for this candidate.

## Deployment and acceptance

After publication, deploy the application and participant images by the digests
recorded by the release workflow. Deployed tests for this candidate on IONOS and
OSC remain pending under #32.

Reference participants for new test tenants are set up with
`scripts/deploy-participant.py`, as documented in
[participant testing](../testing/participant-test.md).
